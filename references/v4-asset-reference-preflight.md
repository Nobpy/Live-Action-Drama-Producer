# V4 资产引用生成前强制自检

本规范是视频生成前的资产硬门禁。只检查和修正资产需求、平台 token 与绑定位置，不改写剧情、镜头、对白、旁白、时间轴或其他 V4 内容。资产自检不能替代 `SCRIPT_SPLIT_PREFLIGHT_PASS`；任一门禁未通过时都禁止点击生成。

## 输入与原则

读取当前分镜剧本原文、剧情边界、V4 平台版提示词、资产目录、注册表、剧梦素材库和提示词编辑器实际 token。

- 剧梦资产引用没有数量上限，需要多少项就完整引用多少项。
- 普通资产名、普通文字 `@名称` 和素材栏图片均不算引用。
- 只有输入 `@` 后从候选列表选择形成的平台 token 才算真实引用。
- 页面唯一 token 集合必须与本镜实际需要的资产集合完全一致。
- 目标是不错用、不漏用、不多用、不猜用。

## 建立 required_asset_keys

完整读取 V4 的基础规格、视觉母版、人物起始状态、各时空与逐秒段落、转场、表演弧线、关键道具和最终结束点，建立去重后的 `required_asset_keys`：

- 每个实际可见主要人物及其当前年龄、时期、LOOK、伤势和状态；
- 每个实际出现的独立场景或时空；
- 实际可见并需要锁定状态的关键道具；
- 必要的群演、生物与交通工具；
- V4 判断为同场景、同时间、未演完故事的 `continuity_link=HARD` 时，上一镜已验收的 `FRAME`；
- 下一镜存在多人、复杂站位、精确遮挡、前中后景或换机位空间关系时的 `STAGING`，不论是否同时使用 `FRAME`。

不得把以下内容计入需求：只出现在“禁止出现”“下一镜才能出现”中的实体；只在旁白中提到但画面没有出现的实体；已被剧情边界排除的角色或场景。同一资产在提示词中多次出现，只按唯一资产 ID 计算一次。

先记录 `continuity_control=NONE | FRAME | STAGING | BOTH`。切到下一天、其他场景、其他时空或新段落时不得错误加入上一镜 `FRAME`；复杂站位不因缺少时间连续性而省略 `STAGING`。

`FRAME` 和 `STAGING` 都是辅助 V4 的视觉控制，不替代 V4，也不替代 `SCENE`、`CHAR`、`LOOK` 或 `PROP`。即使尾帧中已经完整出现环境、人物和道具，也必须同时保留本镜全部基础资产 token；不得因使用首帧控件或 FRAME token 而删除任何必要 SCENE、CHAR、LOOK 或 PROP。`FRAME`/`STAGING` 的范围只覆盖对应镜头。页面首帧控件与提示词 token 是两类状态，使用尾帧法时二者均须分别读取验证。

使用 `FRAME` 或 `BOTH` 时还要检查 V4 时间轴：开头是否存在 1–2 秒同机位、同构图、无新对白、无新剧情、无明显运镜的尾帧识别缓冲；缓冲后是否明确 CUT 到正式机位；总时长是否已为该缓冲单独留量。任一项缺失时标记 `CONTINUITY_PREFLIGHT_BLOCKED`，先修订 V4 再重跑自检。

## 校验每项需求

逐项核对：

1. 类型：CHAR、LOOK、SCENE、PROP 等不得混淆；
2. 身份：人名、年龄、时间线、稳定体貌；
3. LOOK/状态：服装、发型、妆容、伤势、污渍、干湿、昏迷或健康状态；
4. 场景：地点、昼夜、季节、天气、剧情时期、布局、门窗、家具和光线；
5. 道具：版本、持有者、完整/破损/开关和使用前后状态；
6. 注册表：仅 `READY`、`HIGH` 且唯一匹配可引用，连续性范围必须覆盖本镜；
7. 平台：完整名称、缩略图和可取得的平台 ID 与注册表一致。

同名多项、缩略图不符、状态不清或版本冲突标记 `PENDING_CONFIRMATION` 并暂停；候选歧义不能通过另造新资产绕过。

## 读取页面 token 并比较

从编辑器读取真实平台 token，按唯一资产 ID 建立 `actual_page_tokens`，再计算：

```text
missing_assets = required_asset_keys - actual_page_tokens
extra_assets = actual_page_tokens - required_asset_keys
wrong_assets = 身份、类型、LOOK、状态、场景版本或连续性不正确的 token
duplicate_tokens = 同一资产 ID 出现两次及以上的 token
```

- 漏用：需要的资产没有真实 token；
- 多用：引用了本镜不需要或不实际出镜的资产；
- 错用：名称相近但身份、年龄、LOOK、时期、状态或版本错误；
- 重复引用：同一正确资产出现多次。它不等于多用，但应保留语义最清楚位置的一次并移除无必要重复。

## 自动修正

仅对 `READY + HIGH + 唯一匹配` 自动处理：

- 漏用：在对应视觉母版或绑定位置输入 `@`，从候选列表选中完整正确资产；
- 错用：移除错误 token，再选择正确 token；
- 多用：移除不属于本镜需求的 token；
- 重复：保留一次清晰绑定，删除无必要重复。

修正只处理 token 与紧邻的重复普通名称，不得重写其他 V4 内容。存在歧义时列出候选、缩略图差异和原因，等待用户确认。

如果 `missing_assets` 在本地、注册表和平台均无可用候选，先确认它是真正缺失，再完整执行 [missing-asset-generation-loop.md](missing-asset-generation-loop.md)。生成、验收、保存、登记、上传并形成 token 后，从头重跑本自检。

## 审计表与硬门禁

输出并覆盖所有需求和全部页面 token：

| 类型 | 出现时间/剧情节点 | 实际需求 | 应引用完整资产名 | 页面实际 token | 结果 | 原因 |
|---|---|---|---|---|---|---|

结果只使用：`正确`、`漏用`、`错用`、`多用`、`重复引用`、`存在歧义`、`资产缺失`。

修正后必须重新读取页面并重新计算四个集合。只有同时满足以下条件才可输出 `ASSET_PREFLIGHT_PASS`：

```text
missing_assets = 空
extra_assets = 空
wrong_assets = 空
未确认歧义 = 空
所有必要资产均为真实平台 token
页面唯一 token 集合 = required_asset_keys
```

最终报告：

```text
资产引用自检：PASS / BLOCKED
必要资产总数：
页面唯一 token 总数：
正确引用：
漏用：
错用：
多用：
重复引用：
歧义或缺失：
```

PASS 时明确说明：“当前页面唯一资产 token 集合与本分镜 required_asset_keys 完全一致，未发现错用、漏用或多用，允许进入生成参数检查阶段。”

BLOCKED 时明确说明：“资产引用自检未通过，禁止点击生成视频。”未亲眼确认页面 token 状态时一律不得报告 PASS。
