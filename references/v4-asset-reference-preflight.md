# V4.2 资产引用生成前强制自检

本规范是视频生成前的资产硬门禁。只检查和修正资产需求、平台 token 与绑定位置，不改写剧情、镜头、对白、旁白、时间轴或其他 V4.2 内容。资产自检不能替代 `SCRIPT_SPLIT_PREFLIGHT_PASS`；任一门禁未通过时都禁止点击生成。

## 输入与原则

读取当前分镜剧本原文、剧情边界、唯一批准的 V4.2 正文、资产目录、注册表、剧梦素材库和提示词编辑器实际 token。

- 剧梦资产引用没有数量上限，需要多少项就完整引用多少项。
- 普通资产名、普通文字 `@名称` 和素材栏图片均不算引用；正文也不得为了引用而追加这些内容。
- 剧梦默认必须使用页面的`一键引用`：把V4.2正文中已经存在的自然实体名称映射到唯一正确素材，再由平台生成富文本token。不得在正文末尾追加资产清单、占位符或Skill说明来帮助引用。
- 只有一键引用确认后在提示词编辑器中完整渲染的平台token才算真实引用；若页面暂不支持一键引用，才允许输入`@`并从候选列表选择作为降级路线。
- 素材库按钮变灰、显示“已引用”或存在“删除引用资产”按钮，只能证明平台记录过引用动作，不能证明提示词中的 token 仍然有效。
- 页面唯一 token 集合必须与本镜实际需要的资产集合完全一致。
- 目标是不错用、不漏用、不多用、不猜用。

## 一键引用字符预算与临时锚点禁令

在打开页面一键引用前，先用 `scripts/asset_reference_budget_guard.py` 对唯一批准正文和“自然名称 → 平台完整资产名”映射做只读预算检查。只有取得 `ASSET_REFERENCE_BUDGET_PASS` 才能进入页面映射。估算必须按正文中每个自然名称的实际出现次数，计算替换为平台完整资产名后的最坏字符膨胀。

任何以下做法都禁止：

- 把自然名称改成 `_诺拉_`、`@诺拉`、前后加标点或其他符号变体；
- 插入零宽字符、隐藏字符、临时别名、英文缩写、假标签、token 占位词；
- 使用没有自然出现在唯一批准正文中的映射名；
- 在页面报错后直接修改批准正文，再沿用原批准状态；
- 为通过 15000 字符限制而删除必要资产或压缩机位细节。

若预算检查失败，或平台提示一键引用后超过 15000 字符：立即取消本次映射，不得点击确认或生成；恢复唯一批准源并作废此前的正文一致性与资产自检状态。只能返回本地草稿阶段，在用户批准前通过不歧义的代词、身份称谓和上下文承接减少同一实体自然名称的重复次数；不得降低示例级摄影、表演、空间、光线与音效细节。修订后重新运行 V4.2 完整度、旁白、字符预算和用户确认流程，再从头录入与引用。

## 建立 required_asset_keys

完整读取 V4.2 的基础规格、视觉母版、人物起始状态、各时空与逐秒段落、转场、表演弧线、关键道具和最终结束点，建立去重后的 `required_asset_keys`：

- 每个实际可见主要人物及其当前年龄、时期、LOOK、伤势和状态；
- 每个实际出现的独立场景或时空；
- 实际可见并需要锁定状态的关键道具；
- 必要的群演、生物与交通工具；
- V4.2 判断为同场景、同时间、未演完故事的 `continuity_link=HARD` 时，上一镜已验收的 `FRAME`；
- 下一镜存在多人、复杂站位、精确遮挡、前中后景或换机位空间关系时的 `STAGING`，不论是否同时使用 `FRAME`。

不得把以下内容计入需求：只出现在“禁止出现”“下一镜才能出现”中的实体；只在旁白中提到但画面没有出现的实体；已被剧情边界排除的角色或场景。同一资产在提示词中多次出现，只按唯一资产 ID 计算一次。

先记录 `continuity_control=NONE | FRAME | STAGING | BOTH`。切到下一天、其他场景、其他时空或新段落时不得错误加入上一镜 `FRAME`；复杂站位不因缺少时间连续性而省略 `STAGING`。

`FRAME` 和 `STAGING` 都是辅助 V4.2 的视觉控制，不替代 V4.2，也不替代 `SCENE`、`CHAR`、`LOOK` 或 `PROP`。即使尾帧中已经完整出现环境、人物和道具，也必须同时保留本镜全部基础资产 token；不得因使用首帧控件或 FRAME token 而删除任何必要 SCENE、CHAR、LOOK 或 PROP。`FRAME`/`STAGING` 的范围只覆盖对应镜头。页面首帧控件与提示词 token 是两类状态，使用尾帧法时二者均须分别读取验证。

使用 `FRAME` 或 `BOTH` 时还要检查 V4.2 时间轴：开头是否存在 1–2 秒同机位、同构图、无新对白、无新剧情、无明显运镜的尾帧识别缓冲；缓冲后是否明确 CUT 到正式机位；总时长是否已为该缓冲单独留量。任一项缺失时标记 `CONTINUITY_PREFLIGHT_BLOCKED`，先修订 V4.2 再重跑自检。

## 校验每项需求

逐项核对：

1. 类型：CHAR、LOOK、SCENE、PROP 等不得混淆；
2. 身份：人名、年龄、时间线、稳定体貌；
3. LOOK/状态：服装、发型、妆容、伤势、污渍、干湿、昏迷或健康状态；
4. 场景：地点、昼夜、季节、天气、剧情时期、布局、门窗、家具和光线；
5. 道具：版本、持有者、完整/破损/开关和使用前后状态；
6. 注册表：仅 `READY`、`HIGH` 且唯一匹配可引用，连续性范围必须覆盖本镜；
7. 平台：完整名称、缩略图和可取得的平台 ID 与注册表一致。

同名多项、缩略图不符、状态不清或版本冲突标记 `PENDING_CONFIRMATION` 并暂停；候选歧义不能通过另造新资产绕过。

## 读取页面 token 并比较

从编辑器读取真实平台 token。每个 token 必须同时通过完整性检查：可读取唯一资产 ID；可识别资产名称或缩略图；节点具有非零可见宽高；不是空壳 span/div；没有因整段粘贴、全量替换、敏感词修订或撤销操作丢失 payload。任一条件不满足即为 `malformed_token`，不得计入 `actual_page_tokens`。平台显示“成功完成 N 处一键引用”和 DOM 中存在 N 个 token 外壳都不是通过证据；必须逐个验证载荷。若正文可见位置出现空白断口、节点无名称/缩略图/资产 ID，哪怕计数正确也必须判定损坏。使用尾帧首帧控件导致素材栏显示状态变化时，同样不得从灰色按钮反推 token 有效。

按唯一资产 ID 建立 `actual_page_tokens`，再计算：

```text
missing_assets = required_asset_keys - actual_page_tokens
extra_assets = actual_page_tokens - required_asset_keys
wrong_assets = 身份、类型、LOOK、状态、场景版本或连续性不正确的 token
duplicate_tokens = 同一映射位置出现两个及以上相邻 token，或同一资产被建立了重复映射行
malformed_tokens = 只有引用节点外壳但无资产 ID、名称/缩略图或可见尺寸的 token
```

- 漏用：需要的资产没有真实 token；
- 多用：引用了本镜不需要或不实际出镜的资产；
- 错用：名称相近但身份、年龄、LOOK、时期、状态或版本错误；
- 同一正确资产因其自然名称在V4.2正文中出现多次，而被一键引用渲染到所有匹配位置，不属于多用或重复引用；资产引用没有数量上限，不得为了减少token而删改正文。
- 重复引用：同一自然名称建立了重复映射行，或同一语义位置出现相邻重复token。只移除重复映射或异常相邻token，不删除一键引用在不同自然语义位置产生的正常token。
- 损坏引用：素材栏可能仍显示已引用，但提示词 token 已成为零宽空节点或 payload 丢失；按漏用处理并重新绑定。

## 自动修正

仅对 `READY + HIGH + 唯一匹配` 自动处理：

- 漏用：重新打开`一键引用`，把正文已有自然实体名映射到完整正确资产并确认；
- 错用：在一键引用映射表中改为正确资产后重新确认；
- 多用：从一键引用映射表删除不属于本镜需求的映射；
- 重复：删除重复映射行或同一位置的异常相邻token；不同语义位置的同资产token全部保留。

修正只处理一键引用映射和平台token，不得重写V4.2正文。映射名必须来自批准正文中的自然实体名称，并避免使用会误伤其他词语的过短子串；例如角色名应使用“黑松堡守卫”而非可能嵌入“守卫长”的“守卫”。存在歧义时列出候选、缩略图差异和原因，等待用户确认。

禁止把下划线包裹名、符号变体、零宽字符、临时别名或假占位词当成“自然实体名称”。一键引用失败时不得退回这类做法。任何 `malformed_token` 都会立即触发生成硬阻断；在恢复批准正文、重做一键引用并逐个验证载荷之前，不得点击生成，也不得把节点数量写成 PASS 依据。

任何对提示词正文的全量替换、敏感词修订、整段粘贴、撤销/重做或编辑器模式切换，都可能破坏富文本 token。发生上述操作后必须把先前的 `ASSET_PREFLIGHT_PASS` 作废，恢复批准的V4.2源正文，重新逐字符核验，再从头执行一键引用和token完整性检查；绝不能沿用素材库按钮状态或旧计数。

如果 `missing_assets` 在本地、注册表和平台均无可用候选，先确认它是真正缺失，再完整执行 [missing-asset-generation-loop.md](missing-asset-generation-loop.md)。生成、验收、保存、登记、上传并形成 token 后，从头重跑本自检。

## 审计表与硬门禁

输出并覆盖所有需求和全部页面 token：

| 类型 | 出现时间/剧情节点 | 实际需求 | 应引用完整资产名 | 页面实际 token | 结果 | 原因 |
|---|---|---|---|---|---|---|

结果只使用：`正确`、`漏用`、`错用`、`多用`、`重复引用`、`存在歧义`、`资产缺失`。

修正后必须重新读取页面并重新计算四个集合。只有同时满足以下条件才可输出 `ASSET_PREFLIGHT_PASS`：

```text
missing_assets = 空
extra_assets = 空
wrong_assets = 空
malformed_tokens = 空
未确认歧义 = 空
ASSET_REFERENCE_BUDGET_PASS
所有必要资产均为真实平台 token
页面唯一 token 集合 = required_asset_keys
```

最终报告：

```text
资产引用自检：PASS / BLOCKED
必要资产总数：
页面唯一 token 总数：
正确引用：
漏用：
错用：
多用：
重复引用：
损坏引用：
歧义或缺失：
```

PASS 时明确说明：“当前页面唯一资产 token 集合与本分镜 required_asset_keys 完全一致，未发现错用、漏用或多用，允许进入生成参数检查阶段。”

BLOCKED 时明确说明：“资产引用自检未通过，禁止点击生成视频。”未亲眼确认页面 token 状态时一律不得报告 PASS。
