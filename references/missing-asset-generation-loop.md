# 缺失资产自动补全、验收、上传与引用闭环

本规范仅在 V4.2 资产引用自检确认当前分镜的必要资产确实不存在时执行。它把“缺失”变成“生成、验收、登记、上传、引用、复检”的闭环，不能用来绕过候选歧义，也不能借机重做已有可用资产。用户明确要求只检查、不生成资产时，报告缺失并暂停。

## 先确认确实缺失

依次检查资产根目录及全部子目录、注册表的标准名/别名/平台名、本地中英文名/简称/旧称、剧梦素材库同名或相似候选、缩略图，以及同一实体的其他时期、LOOK 或状态。只有搜索完整且没有满足当前连续性的可用资产时，才进入补全。

流程中的 `MISSING_CONFIRMED`、`GENERATION_QC` 和 `GENERATION_FAILED` 是审计状态，可写在报告或注册表 `notes`；注册表正式 `status` 仍按既有字段使用，只有最终验收通过的文件才能标记 `READY`。

## 分类与需求说明

将缺失项分类为：

- `NEW_CHARACTER`：全新剧情人物；
- `EXISTING_CHARACTER_NEW_LOOK`：同一人物缺少年龄、服装、伤势或状态版本；
- `NEW_SCENE`：全新地点；
- `EXISTING_SCENE_NEW_STATE`：同一地点的昼夜、季节、天气、破损、陈设或剧情时期变化；
- `NEW_PROP`：全新道具；
- `EXISTING_PROP_NEW_STATE`：同一道具的完整、破损、开关或使用前后变化。

`STAGING` 站位合成图不属于通用 `SCENE` 缺失资产，而是 V4.2 镜头设计需要的专用视觉辅助资产。通用 `SCENE` 仍必须是 16:9 空场景、完全无人无文字；`STAGING` 可以按 [cross-shot-continuity.md](cross-shot-continuity.md) 把本镜需要的人物放入场景，用来锁定构图与站位，但不得登记为基础场景或替代 `SCENE/CHAR/LOOK/PROP`。

阅读当前原文、V4.2、前后分镜、该实体在全文中的出现、世界观、时代、地域、阶层、时间线及现有资产，建立 `asset_generation_brief`：资产类型、标准名、剧情用途、首次出现位置、连续性范围、时代/世界观、状态、必须继承与必须区分的特征、身份参考与风格参考、构图、必须出现/禁止出现、文件名和 asset_key。信息不足时继续阅读上下文甚至全文，不得只凭当前一句猜测。

默认使用可用的内置图像生成/编辑能力。现有本地图片作为编辑目标前先实际查看；项目使用的最终图必须保存到项目资产目录，不能只留在生成工具默认目录。多个不同资产分别生成，不把不同资产当成同一提示词的随机变体。

## 人物资产

### 全新人物

依据全文确定性别、准确年龄段、身份、阶层、职业、性格、剧情处境、发型、服装、鞋履、饰品、妆容、伤势、疲惫与污渍。现有人物图只作为项目摄影、写实程度、服装时代、色彩和构图参考，不得复制、融合或平均现有人物面孔。

把候选脸与现有人物逐项比较脸型、发际线、眉形、眼形/眼距、鼻梁/鼻翼、嘴唇、颧骨、下颌、年龄感、发色/发型和胡须。除非剧本明确同卵双胞胎，新人物必须清楚可辨，禁止近似脸、换发型式复用和疑似同一张脸。血缘关系可有合理家族特征，但仍须明显是不同人物。所有新生成的人物资产不得出现亚洲人脸，并应与项目既有真人选角体系一致。

### 同一人物的新 LOOK/状态

必须以该人物已确认资产作为身份参考，保持同一张脸、骨相、稳定体貌和同一时间线下的年龄，只改变剧本要求的服装、发型、妆容、伤势、污渍、干湿、昏迷/健康等状态。童年、成年和老年版本应自然重建年龄差异，不能机械缩放。每次编辑重复：“只改变指定 LOOK 或状态，保持人物身份与未点名内容不变。”如果同一人物参考与“不得出现亚洲人脸”的项目硬约束冲突，不得擅自换脸，标记歧义并询问用户。

人物提示词骨架：

```text
Use case: photorealistic-natural / identity-preserve
Asset type: 真人短剧人物资产
Primary request: 生成[角色名]在[剧情时期/状态]下的人物资产。
Input images: [同一人物身份参考；其他图片仅为项目风格参考，禁止复制其面孔]
Subject: [性别、年龄、身份、阶层、体貌、发型、服装、鞋履、饰品、妆容、伤势和状态]
Style/medium: 高预算完全写实真人短剧资产摄影，真实皮肤、骨骼、布料和自然光影。
Composition/framing: 继承项目人物资产画幅、人物比例与构图规范，身份清楚。
Constraints: 新人物与所有现有人物面部明显不同；同一人物新LOOK严格保留身份；不得出现亚洲人脸；服装和状态符合剧本与时代；只出现目标人物；无文字、字幕、标志或水印。
Avoid: 亚洲人脸、相似脸、重复脸、名人脸、现代错代服装、动漫、游戏CG、塑料皮肤、过度磨皮、肢体畸形、多余人物、文字、水印。
```

## 场景资产

### 全新场景

依据全文确定地点性质、时代、建筑风格、地域、气候、室内外、昼夜、季节、天气、剧情时期、阶层、布局、门窗、家具、关键陈设、光源、材质与新旧/破损状态；参考现有场景统一世界观、建筑语言、材质、色彩、光比、写实程度、镜头高度和景别。

场景固定为 16:9 横版空场景，不得出现人物、群演、人形轮廓、人物倒影、人物影子、角色肖像、可识别人脸或任何文字，包括字幕、招牌字、书页可读文字、屏幕文字、Logo 和水印。只加入剧情需要的建筑、家具、自然环境和物件。

### 同一场景的新状态

必须以现有场景为编辑目标，保留建筑结构、房间尺寸、摄影机角度、透视、门窗位置、家具主布局、楼梯/壁炉/柱子/道路等锚点和主要材质，只改变明确要求的昼夜、天气、季节、破损、潮湿、火灾后或陈设状态。每次编辑重复：“只改变指定状态，保持空间几何、机位、构图、门窗、家具主布局和未点名元素不变。”结果同样必须 16:9、完全无人、完全无文字。

场景提示词骨架：

```text
Use case: historical-scene / lighting-weather / precise-object-edit
Asset type: 真人短剧空场景资产
Primary request: 生成[场景名]在[时间/天气/剧情状态]下的场景资产。
Input images: [同一场景编辑目标；其他项目场景仅为风格参考]
Scene/backdrop: [时代、地域、建筑、室内外、布局、门窗、家具、地貌、天气和状态]
Style/medium: 高预算真人短剧实景电影摄影，真实建筑、材质和自然光线，与项目场景统一。
Composition/framing: 16:9 横版，完整建立空间和关键锚点。
Constraints: 绝对无人、无人影/倒影/肖像；绝对无文字、字幕、Logo或水印；同一场景状态变体保持原空间几何、机位、透视、门窗和主布局，只改变指定状态。
Avoid: 人物、群演、人影、人脸、文字、现代错代物件、错误建筑风格、空间重构、布局漂移、动漫或游戏CG感。
```

## 道具资产

依据剧本确定用途、时代、阶层、材质、工艺、尺寸、新旧程度和完整/破损/开关/使用后状态。必须符合世界观、地域和技术水平，禁止现代塑料、电子产品、错误工业工艺、不合时代的枪械/机器/包装/印刷品、无依据魔法结构或现代医学器械。

同一道具已有其他状态时优先编辑原资产，保持形状、比例、材质和识别特征，只改变剧情需要的状态。结果不出现人物、手持展示者、无关物件、文字、Logo 或水印。

道具提示词骨架：

```text
Use case: product-mockup / precise-object-edit
Asset type: 真人短剧关键道具资产
Primary request: 生成[道具名]在[剧情状态]下的生产参考图。
Input images: [同一道具已有版本；项目世界观和材质风格参考]
Subject: [用途、时代、材质、工艺、尺寸、新旧程度和状态]
Style/medium: 完全写实影视道具摄影，真实材质、磨损与工艺。
Composition/framing: 单一道具完整清楚，无遮挡。
Constraints: 符合剧本时代、地域、阶层与技术水平；状态变体保持原形状、比例、材质和识别特征；无人物、手、文字、Logo或水印。
Avoid: 现代错代物件、塑料玩具感、错误技术、无关装饰、人物、手、文字、动漫或游戏CG。
```

## 视觉验收与停止条件

必须实际查看每张生成结果。

- 人物：身份、年龄、服装、状态、项目风格；新人物不撞脸且无亚洲人脸；同一人物不换脸；无多余人物、肢体畸形、文字或水印。
- 场景：16:9、地点/状态正确、风格统一、完全无人无文字；状态变体保持原结构、机位和布局；无错代和空间变形。
- 道具：世界观、时代、材质、工艺与状态正确；无错代、人物、手、文字或水印；状态变体保持原识别特征。

任一项失败不得置为 `READY`。每项资产最多三轮针对性修正，每轮只修上次失败点并重申全部不变量。三轮仍失败，或图像工具不可用/无输出，标记 `GENERATION_FAILED`，报告原因并暂停本镜；禁止跳过资产、禁止点击视频生成。

## 保存、登记、上传和引用

通过验收后：

1. 建立唯一 asset_key 和不覆盖旧文件的版本化文件名；
2. 保存或复制到项目资产目录；
3. 计算 file_size、modified_time、sha256；
4. 新增或更新注册表，`match_confidence=HIGH`、`status=READY`，`match_basis` 写明 `generated from script context + project style references + visual QC passed`，并写 continuity_scope；
5. 上传剧梦，核对完整名称、缩略图与本地最终图并记录 platform_asset_id；
6. 加入 `required_asset_keys`，把批准的 V4.2 正文逐字符放入剧梦后，通过页面一键引用形成真实富文本 token；不得改写正文或追加资产清单；
7. 不得把失败候选、旧错误版本和新正确版本同时引用；
8. 从头执行 [v4-asset-reference-preflight.md](v4-asset-reference-preflight.md)。

只有所有生成资产均已通过视觉验收、落盘、登记、上传并形成 token，且最终 `missing_assets`、`extra_assets`、`wrong_assets` 和未确认歧义均为空时，才可输出 PASS。否则必须输出：“缺失资产补全或引用自检未通过，禁止点击生成视频。”
