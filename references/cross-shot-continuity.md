# V4 连续分镜视觉辅助规范：尾帧法与站位合成图法

本规范在 V4 已完成剧情拆镜和下一镜导演设计后执行。V4 是分镜主体，负责剧情边界、动作过程、表演、摄影机、声音和结束点；尾帧法与站位合成图法是辅助 V4 落地的两种视觉控制手段，分别解决时间连续和复杂空间调度问题。

## 正确执行顺序

1. 先按 V4 阅读剧本、确定剧情边界、设计分镜并写出下一镜导演意图；
2. 判断相邻分镜是否为同一场景、同一时间、同一段尚未演完的故事、动作或对白；
3. 若是，标记 continuity_link=HARD 并启用尾帧法；
4. 再独立判断下一镜是否存在多人、复杂站位、精确遮挡、换机位后空间关系或关键道具位置需要预设；
5. 若有，启用站位合成图法；
6. 把选定的视觉辅助资产写回 V4，完成一致性自检后才生成。

先有 V4 的剧情与镜头方案，再选择辅助控制。不能先为了使用尾帧或站位图而反向扭曲剧情拆镜。

## 两个独立判断维度

尾帧法与站位合成图法不是互斥方案，也不是谁失败后才使用另一个。它们分别由不同条件触发：

| 判断维度 | 是 | 否 |
|---|---|---|
| 下一镜是否紧接同场景、同时间、未演完的故事、动作或对白？ | 使用 FRAME 尾帧法 | 不使用尾帧控制 |
| 下一镜是否需要精确控制多人、站位、朝向、遮挡、前中后景或复杂构图？ | 使用 STAGING 站位合成图法 | 不强制制作站位图 |

最终记录：

    continuity_control: NONE | FRAME | STAGING | BOTH

| 剧情连续性 | 空间调度复杂度 | 控制结果 |
|---|---|---|
| 非紧接：下一天、明显时间跳转、其他场景或新段落 | 简单 | NONE |
| 紧接：同场景、同时间、故事或动作尚未演完 | 简单 | FRAME |
| 非紧接 | 复杂 | STAGING |
| 紧接 | 复杂 | BOTH |

BOTH 表示两种方法同时辅助 V4：FRAME 保证上一镜真实尾态不穿帮，STAGING 保证下一镜目标机位与复杂站位准确。

## 连续性分级

- HARD：同一场景、同一时间、同一故事段落，动作、对白、眼神、移动或道具操作跨镜继续；必须使用尾帧法。
- SOFT：仍在同一地点，但有明确时间跳转、插入镜头、蒙太奇间隔或新一段行动；不强制尾帧，可按空间复杂度使用站位图。
- NONE：切到下一天、其他场景、其他时空或没有直接承接关系；不使用尾帧，可按空间复杂度使用站位图。

同一个场景本身不等于 HARD。只有故事时间和动作链也连续、上一镜没有演完而被时长迫使拆开时，才启用尾帧承接。切到下一天或其他场景时，即使人物相同，也不应拿上一镜尾帧锁下一镜。

HARD 连续性簇必须顺序生成。上一镜真实视频未完成和未 QC 前，可以提前写下一镜 V4 草稿或设计 STAGING，但不能定稿下一镜首态和生成视频。

## 方法一：尾帧法——辅助 V4 的时间连续

### 触发条件

只要下一镜是 HARD 紧接镜头，就必须从上一镜真实生成视频提取可用尾帧；不能仅依靠 V4 文字重新猜站位和状态。

若下一镜已切到下一天、其他场景、明显时间跳转或新的叙事段落，则不使用尾帧控制。不要把上一镜的瞬时状态错误带入新的时空。

### 提取候选帧

下载并确认上一镜文件后，运行：

    python scripts/extract_continuity_frames.py 上一镜.MP4 候选输出目录 --window 1.2 --count 6

脚本从结尾前的稳定窗口提取多个候选帧并输出时间码。若 FFmpeg 不在 PATH，传入 --ffmpeg 和 --ffprobe 的绝对路径。

逐张实际查看，选择最接近剧情结束点且满足以下条件的一帧：

- 无运动模糊、闭眼、半张脸、异常手指或转场叠化；
- 人物位置、身体朝向、头部、视线和左右手清楚；
- 关键道具、门窗和场景锚点可判断；
- 服装、伤势、湿度、污渍和光线状态正确；
- 位于动作结束或动作余势可自然延续的时刻；
- 不提前包含下一镜剧情。

不要机械使用视频文件最后一帧；片尾黑帧、淡出、运动模糊或压缩异常不能作为连续性首帧。选中的文件命名建议：

    FRAME-EP{集}-S{上一分镜}-END-V01__{时间码}.png

### 连续性移交

使用 [continuity-handoff-template.json](../assets/continuity-handoff-template.json) 建立移交记录，至少写明：

- 来源视频、时间码与尾帧文件；
- 摄影机侧位、景别、焦段感和轴线侧；
- 每个人的画面左右、前中后景、朝向、姿态、重心、视线和手部；
- 角色身份、LOOK、发型、妆容、伤势、污渍和干湿；
- 道具由谁持有、哪只手、位置、朝向与状态；
- 门窗、家具、场景锚点和光线方向；
- 动作余势与下一镜第一动作；
- 允许改变与绝对不许改变的内容。

下一镜 V4 必须吸收这些真实可见事实，并从动作余势继续；已经完成的动作不得重演。

### 在剧梦中使用

平台存在首尾帧或首帧能力时，把选定 FRAME 设置为下一镜首帧，并重新读取控件状态和缩略图确认成功。只有普通素材栏或提示词中出现文件名不算设置首帧。

如果当前平台或模型不支持首帧控制，把 FRAME 作为独立参考资产上传并形成真实引用，同时在 V4 中明确它负责锁定上一镜真实结束状态；必须如实报告所用方式，不能假装首帧控件已经设置。

### 1–2 秒尾帧识别缓冲与剪辑手柄

凡 continuity_control 为 FRAME 或 BOTH，下一镜开头必须预留 1–2 秒尾帧识别缓冲。它有两个用途：先让视频模型稳定识别上一镜的环境、场景几何、人物身份与站位、LOOK、道具、光线和动作余势；再为后期提供可裁切、覆盖或选择切点的剪辑手柄。

缓冲段必须：

- 第一帧直接继承已选 FRAME；
- 机位、景别、构图、透视、轴线、人物位置、朝向、姿态、手部、道具、门窗、家具和光线与上一镜结尾保持一致；
- 不立即推拉摇移、不改变焦段感、不换景别，不用渐变运镜掩盖机位漂移；
- 不开始新对白、不进入新的剧情节点、不重演上一镜动作；
- 人物只允许自然呼吸、眨眼、布料或头发的极轻微自然变化，不发生会改变站位与状态的动作；
- 持续 1–2 秒后立刻明确 CUT 到 V4 设计的新机位、STAGING 构图或正式动作段，不用缓慢漂移代替 CUT。

这 1–2 秒属于模型识别和后期剪辑余量，不是有效剧情内容。它计入平台生成总时长，但不计入对白、旁白占位或新剧情的可用时长；拆镜与音频容量预检必须提前为它留出时间。交付时记录实际缓冲范围和建议 CUT 点，但本 Skill 不擅自裁剪画面。

## 方法二：站位合成图法——辅助 V4 的空间调度

### 触发条件

当下一镜需要精确控制开场构图和人物空间关系时使用 STAGING，无论它是否紧接上一镜。典型情况：

- 多人同场，前中后景、左右站位、朝向、视线或遮挡复杂；
- 人物与门、桌、床、楼梯、车辆或关键道具的距离必须准确；
- 下一镜换机位、换景别或做正反打，需要预先展示新视角下的站位；
- 导演需要直接定义下一镜的理想第一画面；
- 新的一天或新场景不需要尾帧，但人物较多或调度复杂。

因此：

- HARD + 复杂站位：使用 BOTH；
- SOFT/NONE + 复杂站位：只使用 STAGING；
- HARD + 简单站位：只使用 FRAME。

STAGING 是镜头级构图与站位控制资产，不是通用空场景资产，也不替代 V4。

### 输入图角色

生成前实际查看每张输入并标注用途。可依据下一镜 V4 的构图方案采用下列组合：

- 原始空场景 + 各角色身份和当前 LOOK + 关键道具；
- 实际尾帧 + 原始空场景 + 各角色身份和当前 LOOK；
- 在 BOTH 模式下，使用真实尾帧提供连续性事实，同时用原始场景与人物资产重建下一镜目标机位。

不存在尾帧不行才做站位图的条件，也不存在无条件必须先编辑尾帧的要求。选择编辑基底只由 V4 的下一镜构图方案和保持连续性的需要决定。不得把不同角色参考图平均融合成相似脸。

### 站位合成提示词骨架

    Use case: compositing / identity-preserve
    Asset type: 连续分镜站位合成图（STAGING）
    Primary request: 根据第[集]-[分镜]的 V4 镜头设计制作真人短剧站位参考图，只锁定开场构图、空间、人物站位、朝向、姿态、相对尺度、遮挡和道具状态。
    Input images:
    - Image 1: [原始空场景或实际尾帧；说明负责锁定的空间或连续性事实]
    - Image 2-N: [逐个人物身份与当前 LOOK 参考]
    - Other: [关键道具或状态参考]
    Scene/backdrop: [固定空间锚点、目标机位、景别、轴线、光线]
    Subject/blocking:
    - [角色A]位于[画面位置或前中后景]，身体朝向[对象]，姿态和左右手为[状态]
    - [角色B]……
    - [关键道具]位于[位置]，由[角色或手]持有，状态为[状态]
    Style/medium: 高预算完全写实真人短剧画面，真实皮肤、布料、材质、透视与自然光线，匹配项目现有资产。
    Composition/framing: 16:9 站位参考图；保持真实比例、遮挡关系、地面接触和透视。
    Constraints: 只改变 V4 明确设计的机位、构图或站位；保持人物身份、LOOK、场景几何、门窗、家具、道具、光线和适用的连续性事实；无文字、字幕、Logo 或水印；不新增人物或物件。
    Avoid: 换脸、相似脸、换衣、人物漂浮、比例错误、镜像、无依据换边、跨轴、门窗换位、家具重构、肢体粘连、手指畸形、文字、水印、动漫或游戏 CG 感。

### STAGING 验收

必须逐项比较 V4、场景和所有人物资产；若为 BOTH，同时比较连续性移交：

- 人物数量、身份、脸、LOOK、年龄和状态正确；
- 站位、前中后景、朝向、视线、左右手、遮挡和相对尺度符合 V4；
- 脚与地面接触真实，无漂浮、穿模或肢体粘连；
- 场景结构、目标机位、透视、门窗、家具和光线没有无授权变化；
- 道具持有者、手、位置、朝向和状态正确；
- BOTH 模式下与真实尾态或明确的镜头过渡不矛盾；
- 无新增人物、无文字、无水印。

单张站位图最多三轮针对性修正。仍失败则不得引用或生成下一镜，报告具体失败项。

## V4 与两种辅助方法的分工

| 内容 | 主要负责者 |
|---|---|
| 本镜演到哪里、下一镜从哪里继续 | V4 |
| 是否属于同场景同时间且故事未演完的紧接镜头 | V4 拆镜判断 |
| 上一镜真实结束状态和动作余势 | FRAME |
| 下一镜目标机位下的复杂构图与站位 | STAGING |
| 人物身份、LOOK、空间本体、关键道具本体 | CHAR/LOOK/SCENE/PROP |
| 动作如何发生、摄影机如何切换或运动、表演和声音如何执行 | V4 |

V4 必须明确写出每个引用的职责。视觉辅助资产帮助 V4 更稳定地执行，不能替代 V4 的剧情、表演和镜头语言。

若 V4、FRAME、STAGING 或基础资产互相矛盾，标记：

    CONTINUITY_PREFLIGHT_BLOCKED

依据上一镜真实结果和当前 V4 导演意图修订 V4 和/或 STAGING，必要时重新制作站位图；全部对齐后再生成。不能无视冲突，也不能简单宣称某一项覆盖其他项。

## 资产类型与绑定

- FRAME：上一镜实际视频中选出的连续性帧，键建议 FRAME-EP{集}-S{镜}-END-V01；
- STAGING：下一镜专用站位合成图，键建议 STAGING-EP{集}-S{下一镜}-OPEN-V01。

选用的控制资产必须保存到项目资产目录、计算指纹并登记；只在对应分镜范围内使用，不得跨场景复用。

FRAME 和 STAGING 均不替代基础资产。即使 FRAME 已完整显示场景、人物和道具，下一镜仍必须正常引用正确的 SCENE、每个出镜人物的 CHAR 与 LOOK、实际可见关键 PROP。下一镜 required_asset_keys 按所选模式包含：

    FRAME（continuity_control 为 FRAME 或 BOTH）
    STAGING（continuity_control 为 STAGING 或 BOTH）
    SCENE
    每个实际人物的 CHAR
    每个实际人物的 LOOK
    实际可见关键 PROP

## 下一镜首秒与 QC

紧接镜头先用 1–2 秒缓冲帮助模型识别上一镜真实世界，再通过明确 CUT 进入有效剧情：

    上一镜真实结束状态 → 保持同机位同构图 1–2 秒 → 明确 CUT 到 V4 或 STAGING 所示机位 → 动作余势继续 → 新动作发生

生成后检查下一镜前 1–2 秒：

- 使用 FRAME：比较真实尾态，检查缓冲段是否保持同机位、同构图、同站位和同状态，且没有新对白、新剧情或明显运镜；
- 使用 STAGING：比较目标机位、构图、站位、朝向、遮挡和相对尺度；
- 使用 BOTH：先检查 FRAME 缓冲，再检查缓冲后是否明确 CUT 到 STAGING 目标构图，并确认物理世界没有跳变；
- 使用 NONE：按 V4 和基础资产检查新时空建立，不应错误继承上一镜瞬时尾态。

任一关键项不一致即标记 CONTINUITY_FAIL 并记录时间码。视频仍遵守一镜只生成一次；未经用户明确授权不得自行重抽。

## 生成前门禁

下一镜只有满足以下条件才可生成：

- V4 已先确定剧情边界、时空关系和下一镜导演设计；
- 已分别完成是否紧接和是否复杂站位两个判断；
- 已明确 continuity_link 与 continuity_control=NONE | FRAME | STAGING | BOTH；
- HARD 镜头已选定实际尾帧，连续性移交完整，首帧控件或引用已验证；
- FRAME 或 BOTH 镜头已在 V4 时间轴开头预留 1–2 秒尾帧识别缓冲，缓冲内无新对白、新剧情和明显运镜，随后有明确 CUT；
- 使用 STAGING 时，站位合成图已通过视觉验收并形成真实 token；
- 使用 BOTH 时，两项均已验证，V4 明确各自职责和机位过渡；
- FRAME/STAGING/SCENE/CHAR/LOOK/PROP/V4 相互一致；
- 页面 token、首帧控件和平台设置已经重新读取验证；
- V4 资产引用自检为 PASS，且不存在 CONTINUITY_PREFLIGHT_BLOCKED。

不得仅凭 V4 写得很详细就跳过紧接镜头必需的尾帧和识别缓冲；也不得因为使用了尾帧就省略基础场景、人物、LOOK、道具资产，或因为不需要尾帧就忽略复杂多人镜头所需的站位合成图。
