# Live-Action-Drama-Producer

用于通过剧梦制作真人 AI 短剧的 Codex Skill。

它能够从本地剧本和资产目录开始，完成拆镜、V4 提示词、资产补全与引用、连续性控制、视频生成与 QC、旁白回填，以及独立 BGM 推荐。

当前稳定版本：**v1.5.1**

## 主要功能

| 模块 | 功能 |
|---|---|
| 剧本拆镜 | 区分现场对白、旁白、动作和场景说明，按 4–30 秒容量设计分镜 |
| V4 提示词 | 生成导演级逐秒执行稿，锁定剧情边界、表演、摄影机、声音和结束点 |
| 资产管理 | 登记人物、LOOK、场景、道具、FRAME 和 STAGING，计算文件指纹并检查版本 |
| 缺失资产补全 | 自动生成并验收确认缺失的人物、LOOK、场景和道具 |
| 引用自检 | 检查剧梦真实 `@` token 的错用、漏用、多用、重复和版本错误 |
| 连续性控制 | 使用真实尾帧、1–2 秒剪辑缓冲和人物入景站位合成图防止穿帮 |
| 剧梦生成 | 上传资产、设置模型参数、生成一次、下载并按规则命名 |
| 视频 QC | 检查技术指标、人物身份、LOOK、场景、道具、对白和连续性 |
| 旁白制作 | 根据真实视频对白窗口计算语速、生成 WAV 并输出旁白版视频 |
| BGM | 试听、推荐和下载独立候选，不自动混入视频 |

## 工作流程

1. 读取项目 `引导.md`、剧本和资产目录。
2. 按剧情、对白容量和场景切换设计分镜。
3. 建立资产注册表并匹配本地与剧梦素材。
4. 对确认缺失的资产执行生成、验收、保存、登记和上传。
5. 按 [V4 规范](references/storyboard-director-v4.md) 生成平台提示词。
6. 根据连续性和站位复杂度选择 FRAME、STAGING、BOTH 或 NONE。
7. 在剧梦形成真实资产 token，并执行[生成前自检](references/v4-asset-reference-preflight.md)。
8. 自检通过后生成、下载并检查原视频。
9. 根据真实对白时间轴制作并回填旁白。
10. 推荐并下载独立 BGM 候选。

## 资产处理

支持的资产类型：

- `CHAR`：人物身份；
- `LOOK`：人物当前服装和剧情状态；
- `SCENE`：空场景；
- `PROP`：关键道具；
- `FRAME`：上一镜真实尾帧；
- `STAGING`：下一镜专用站位合成图。

资产会经过本地文件、注册表、平台名称、缩略图和连续性范围核对。只有 `READY + HIGH + 唯一匹配` 的资产允许自动引用。

存在多个候选或身份、LOOK、状态不明确时会暂停询问，不猜选，也不会通过另造资产绕过歧义。

### 缺失资产补全

- 新人物匹配项目风格，不与现有人物撞脸，不出现亚洲人脸；
- 同一人物的新 LOOK 保持身份，只改变指定服装或状态；
- 场景固定为 16:9 空场景，无人物、文字、Logo 和水印；
- 同一场景的新状态保持空间几何、机位、门窗和主布局；
- 道具符合剧本世界观、时代、地域和技术水平。

每项资产最多进行三轮针对性修正。验收通过后才会保存、登记、上传并引用。完整规则见[缺失资产补全规范](references/missing-asset-generation-loop.md)。

## 资产引用自检

普通资产名称、普通文字 `@名称` 或只放进素材栏的图片都不算有效引用。只有从候选列表选中后形成的平台 token 才有效。

生成前会检查：

- `missing_assets`：漏用；
- `extra_assets`：多用；
- `wrong_assets`：身份、LOOK、场景状态或版本错误；
- `duplicate_tokens`：无必要重复。

剧梦资产引用数量没有上限，不能为了减少引用数量而省略必要资产。只有所有问题归零后才获得 `ASSET_PREFLIGHT_PASS`。

## 连续分镜防穿帮

先由 V4 完成剧情拆镜，再分别判断：

| 判断 | 控制方式 |
|---|---|
| 同场景、同时间、同一段剧情尚未演完 | 使用 `FRAME` 尾帧法 |
| 人物多、站位或遮挡复杂、换机位关系需要预设 | 使用 `STAGING` 站位合成图 |

最终状态：

| 时间连续性 | 站位复杂度 | 结果 |
|---|---|---|
| 非紧接 | 简单 | `NONE` |
| 紧接 | 简单 | `FRAME` |
| 非紧接 | 复杂 | `STAGING` |
| 紧接 | 复杂 | `BOTH` |

### 尾帧识别与剪辑缓冲

`FRAME` 或 `BOTH` 镜头开头必须：

- 直接继承上一镜真实尾帧；
- 保持相同机位、构图、站位、人物／道具状态和光线；
- 1–2 秒内不开始新对白、新剧情或明显运镜；
- 缓冲后明确 CUT 到正式机位或 STAGING 构图。

这 1–2 秒用于让生成模型识别上一镜现场，也为后期留下可裁切的剪辑手柄。它计入生成时长，但不计入有效剧情容量。

尾帧和站位图都只辅助 V4，绝不能替代基础资产。使用尾帧时仍须完整引用场景、全部出镜人物、当前 LOOK 和关键道具。

完整规则见[尾帧与站位连续性规范](references/cross-shot-continuity.md)。

## 剧梦与视频规格

默认参数：

- 九梦 2.5 Pro；
- 9:16；
- 480P；
- 单镜 4–30 秒；
- 原视频只有现场对白、环境声和动作音效；
- 无旁白朗读、字幕和 BGM；
- 每个分镜默认只生成一次。

原视频会检查解码、分辨率、时长、黑帧、冻结、音轨、人物身份、LOOK、场景、道具、口型和连续性。异常会记录时间码，但不会擅自重新抽卡。

## 旁白与 BGM

旁白依据下载后视频的真实对白区间安排：

- 默认语速 1.1，安全范围 0.95–1.25；
- 对白区间前后保留 0.35 秒保护；
- 不允许旁白覆盖现场对白；
- 只重编码音频，保持原视频画面和时长；
- 输出纯旁白 WAV、cue sheet 和 `(OV).MP4`。

BGM 至少试听主推荐和一个对照候选，优先器乐和无人声曲目。只下载独立文件，不自动混入视频。

详细规则见[旁白规范](references/narration-mix.md)和[质量控制规范](references/quality-control.md)。

## 使用方法

复制 [`assets/引导.md`](assets/引导.md) 到项目目录并填写参数，然后在 Codex 中调用：

    $live-action-drama-producer

也可以直接发送：

    使用 $live-action-drama-producer 开始制作。
    剧本路径：D:\项目\剧名\剧本.docx
    制作范围：第1集
    资产路径：D:\项目\剧名\资产
    剧梦项目：剧名
    剧梦目标：第1集，从分镜1开始新增
    交付目录：D:\项目\剧名\成片
    生成前：不需要人工确认，符合规则后自动继续

## 输出文件

| 类型 | 命名 |
|---|---|
| 原视频 | `{集数}-{分镜号}.{抽卡序号}.MP4` |
| 旁白版 | `{集数}-{分镜号}.{抽卡序号}(OV).MP4` |
| 集级旁白 | `{集数}.wav` |
| 镜头级旁白 | `{集数}-{分镜号}.wav` |
| 旁白时间表 | `{集数}-{分镜号}.cues.json` |
| QC 报告 | `{集数}-{分镜号}.qc.json` |

最终报告还会列出分镜边界、使用资产、引用自检、尾帧与缓冲范围、补生成资产、QC 结论、旁白参数、BGM 候选和未完成项。
